# Testing

This plugin's risk splits into **three** layers, from cheap-and-certain to
expensive-and-fuzzy:

1. **Deterministic** (`tests/validate.sh`) — structural drift: renames, namespace typos,
   roster/model mismatches, a dependency that won't auto-resolve. Cheap, runs every push.
2. **Behavioral smoke** (`tests/behavioral.sh` + `tests/install-smoke.sh`) — does the
   right panel spin up, does the tracker fall back correctly, does `/deploy`'s gate hold?
   Opt-in, real `claude -p` calls against generated fixtures, run pre-release or on-demand
   (see [ADR 0001](docs/adr/0001-behavioral-test-harness.md) and
   [ADR 0002](docs/adr/0002-behavioral-tests-opt-in-not-push-ci.md)).
3. **Manual (~10 min)** — the residue neither of the above can reach: end-to-end `/work`
   rehearsal, and judgment quality (is a brief's reasoning good, is a ticket well-scoped,
   is a plan sound, does prose read well). No assertion catches taste.

No full eval framework, no LLM-in-CI-on-every-push — that would cost more than the plugin.
Layer 2 exists because the skills emit **mandated one-line announcements** ("Panel: …",
the tracker choice, the computed version) specifically so pass/fail can be checked by a
mechanical read of one line — a human can do that read, and so can ~150 lines of bash.

## Layer 1 — deterministic: `tests/validate.sh`

```
./tests/validate.sh          # bash + jq + grep; exits nonzero on any failure
```

Runs in CI on every push. Checks manifests, structure, frontmatter (incl. the per-role
`model:` tiers and tight tool allowlists), the bare-name reference convention, and the
load-bearing content invariants from `CLAUDE.md` (engineer worktree guard + no-self-merge,
architect never `--admin`, the soundcheck pass, tracker fallbacks, the shared
ticket-draft block). It also runs `claude plugin validate` when the CLI is on PATH. Run it
before every commit.

## Layer 2 — behavioral smoke: `tests/behavioral.sh` + `tests/install-smoke.sh`

Real `claude -p` calls against fixtures generated at runtime into `mktemp -d` (never
committed — see ADR 0002). Opt-in only: never wired into `tests/validate.sh` or `ci.yml`.
Run locally before a release, or via `.github/workflows/behavioral.yml` on
`workflow_dispatch` (gated on the `ANTHROPIC_API_KEY` secret, pinned CLI version).

**This layer proves announcements and gates, not judgment quality.** It confirms a
`SKILL.md` steers the model to the right one-line outcome and that a gate actually holds —
it does not grade whether the reasoning behind that outcome is good. That's what the
manual layer (below) is for; it is not optional just because layer 2 is green.

**ADR 0003 caveat:** the harness invokes the **namespaced** `/workflow:*` form of each
skill (e.g. `/workflow:plan-sprint`), never a bare name. A bare `/plan-sprint` is unsafe
under headless `--plugin-dir`: a stale user-scope `~/.claude/skills/plan-sprint` left over
from before this plugin existed silently shadows the plugin's own skill and produces wrong
panels. If you're running any of these checks by hand, retire old copies from
`~/.claude/skills/` and `~/.claude/agents/` first (see `CLAUDE.md`).

Fixture repo shapes (generated by the harness, matching this table):

| Shape | Marker files | Expected `/plan-sprint` panel |
| --- | --- | --- |
| web app | `package.json`, an `app/` or `web/` dir | architect + product-manager + product-designer |
| infra | `main.tf` (or `helm/`, `k8s/`) | architect + devops-engineer (no designer) |
| data | `dbt_project.yml` (or `dags/`) | architect + data-engineer |
| library/CLI | a bare `Cargo.toml` or `go.mod`, no UI | architect + product-manager |

Check status:

- **#1 Panel selection** — **automated.** `tests/behavioral.d/10-panel.sh` runs
  `/workflow:plan-sprint` against all four fixtures with `--disallowedTools Task` and
  asserts the `Panel: …` line (in `.result`) matches the table above, stopping at the
  approval gate before any tickets are cut. Green via live `claude -p`.
- **#2 No-tracker fallback** — **automated.** Same file: on a fixture with no
  `.claude/tracker.json` and no `gh` remote (and `--mcp-config '{"mcpServers":{}}'
  --strict-mcp-config` so a live Linear MCP server can never leak in), asserts the
  announcement names the `docs/sprint-backlog.md` fallback. The **gh-enabled** tracker
  variant (announcing GitHub Issues via `gh`) is not automated — see the manual layer.
- **#3 `/idea` dispatch** — **manual** (decided; see [ADR 0004](docs/adr/0004-idea-dispatch-check-stays-manual.md)).
  Investigated during implementation (#13): headless `Task`/`Agent` permission enforcement
  is a *probabilistic classifier*, not a hard match on `--disallowedTools`. A blanket
  `--disallowedTools Task` removes the tool entirely (nothing to observe); a subagent-scoped
  deny made the attempt observable but let the real `idea-architect` run on fable ~60% of
  the time (real spend). Since ADR 0001 forbids ever running an unblocked `Task` to make an
  assertion pass, this check cannot be automated safely and stays manual. Brief *quality*
  (2–3 compared approaches + a recommendation) was always a manual/judgment check regardless.
- **#5 `/deploy` dry gate** — **automated.** Fixture: a git repo with a `v0.1.0` tag, a
  `feat:` commit, and a local bare repo as `origin`; `gh` disallowed. Hard assert: tags/refs
  unchanged after the run (the gate held — nothing irreversible fires before the human
  answers). Soft assert: the result text names the correctly computed next version.
- **#6 Dependency auto-install** — **conditional.** `tests/install-smoke.sh` is token-free
  (`CLAUDE_CONFIG_DIR=$(mktemp -d) claude plugin marketplace add thejefflarson/workflow &&
  claude plugin install workflow`) and asserts soundcheck resolves at the `ref` pinned in
  `.claude-plugin/marketplace.json`, exiting nonzero on mismatch — automated *if*
  `claude plugin install` doesn't require interactive login in a fresh config dir.
  Deciding factor: interactive-login is the one genuine unknown here; if the CLI demands
  it, the script degrades to a clean skip with an explicit "interactive login required"
  message and this check stays manual (run once per release, by hand, in a real profile).

## Layer 3 — manual (~10 min)

Run from a session with the working copy loaded — either you're editing in this repo (its
`.claude/` auto-loads project-scoped) or `claude --plugin-dir ~/dev/workflow`. Retire any
stale `~/.claude/skills/*` or `~/.claude/agents/*` copies first (ADR 0003, above).

### `/work` rehearsal
On a real-but-safe repo (or a scratch fork) with one trivial ready ticket:
- the engineer's result shows a worktree path under `.claude/worktrees/`;
- it opened a PR and **stopped** (PR open, unmerged, no auto-merge enabled);
- `/soundcheck:security-review` visibly ran **from the main loop**;
- if you let the architect proceed, the merge is a normal `--squash` — grep the transcript
  for `--admin` and confirm it's **absent**.

### Tracker fallback, gh-enabled variant
In a `gh`-enabled fixture without Linear config, run `/plan-sprint` and confirm it
announces GitHub Issues via `gh`. Stop at the gate — never approve, so no tickets are cut.

### Judgment quality (brief / ticket / plan / prose)
Neither layer above grades reasoning quality — only whether a mandated line appeared or a
gate held. By hand, spot-check:
- `/idea`'s brief has **2–3 genuinely compared approaches + a recommendation**, not a
  rubber-stamp of the input;
- `/plan-sprint`'s tickets are well-scoped and match the chosen panel's expertise;
- ADR wording and the agents' "intellectual lineage" sections read as intended.

Don't snapshot skill text (every intentional edit would break it) — the targeted substring
checks in `validate.sh` cover only the load-bearing lines. Don't mock Linear/`gh`/git — the
integration surface is Claude Code itself, which can't be meaningfully mocked. Soundcheck
has its own tests; here we only assert the reference and the pin exist.
